How to submit — every step, nothing left out

  1. Download the file. ⬇ gemsdoekarage2-gbm-offcat-a5-n100000-20261031T020958Z.tif (360,319 bytes). It is a single-band float32 GeoTIFF, EPSG:32611, 3730 × 3292, 100 m, matching the official template exactly.
  2. Verify it yourself before uploading (optional but recommended). 
    sha256sum gemsdoekarage2-gbm-offcat-a5-n100000-20261031T020958Z.tif
# expect: 18f2225b9af79d381f15aa46343805a7e167db6fd9e33934a464789d2b85cc1e
    If the hash differs, the download is corrupt — do not upload it.
  3. Sign in and open the submission page. https://www.drivendata.org/competitions/306/competition-doe-gems/submissions/ ↗ then choose New submission.
  4. Choose the file. Under File to submit, select the .tif you downloaded. DrivenData accepts a single-band GeoTIFF, or a .zip containing exactly one GeoTIFF. Do not add .aux.xml, .ovr or any sidecar file to the zip.
  5. Paste the note. Use this exact string so you can tell the entry apart later (124 characters, under the 140 limit): 
    GBM fault prospectivity from the 19 GeoDAWN bands; top 100k off-catalogue pixels, 500 m catalogue apron, binary 0/1, no NaN.
  6. Create the submission and wait for scoring. If you see "Predicted values must be in range [0, 1]", that is the whole-array NaN failure described under IR-EXTERIOR-01 — this file cannot trigger it, because every one of its 12,279,160 values is finite and in [0, 1]. If you see it anyway, report the exact message.
  7. Record the receipt. Copy the score and the submission ID back into this repository so the value stops being a projection and becomes an ORGANIZER-CONFIRMED number.

Evidence labels used on this site. ORGANIZER-CONFIRMED — copied from an actual submission-page receipt. None exists locally; this project has no DrivenData session. USER-REPORTED / UNVERIFIED — a leaderboard value pasted from the project prompt, with no file-linked receipt. HOLDOUT-DTI-PROXY — a local hide-and-recover score against the PUBLIC catalogue, which is not the competition truth. MODEL-PROJECTION — a number produced by a stated model with stated assumptions. It is not a score and must never be reported as one. RASTER-MEASUREMENT — computed directly from pinned TIFF bytes.
