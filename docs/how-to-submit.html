Step-by-step: how to make a submission (when eligible)

Official rules, verified (NLR rules PDF, §1.1 and §3.2): one entry per competitor; a single GeoTIFF with a single raster layer at 100 m; submission limit three submissions per week; generative-AI use must be described in the narrative. The problem page (page 967) specifies values between 0 and 1, float32, and null or NaN outside the bounds.

  1. Run an assigned lane using the shared feature stack, evaluate_holdout.py and submission_writer.py. Stop immediately if the pre-placement surface is a duplicate (Spearman > 0.90 or >70% of dots within 3 px of any registry raster's dots).
  2. Use buffered whole-segment hide-and-recover. Build all catalogue-based features from visible faults only; mask visible faults pixel-exactly. Compare pooled DTI (alpha 0.2, beta 0.8, 300 m triangular kernel) against the incumbent with a paired 95% interval.
  3. Test every feature alone for leakage. AUC above 0.90 means leakage until proven otherwise.
  4. Validate the final TIFF. Single float32 band; matching CRS/EPSG:32611, shape 3730×3292, and geotransform; values in [0,1] inside the footprint; NaN outside the footprint. This addresses the "Predicted values must be in range [0, 1]" portal error — zero-exterior files triggered it; NaN-exterior files pass the range check.
  5. Check uniqueness against the full registry. No registry raster may have |Spearman| > 0.90 or >70% dot overlap within 3 px.
  6. Only after every automated gate passes: a separate selector checks the account quota (up to three scored attempts per week, one final selection).
  7. Download the approved .tif, verify its SHA-256 against the receipt, sign in to the DrivenData submissions page, choose the file, and use the recorded unique name and a short note no longer than 140 characters. Save the actual organizer receipt as ORGANIZER-CONFIRMED; never convert a local projection into a score.
