📌 The submission form

File to submit: a single-band GeoTIFF (.tif), or a .zip containing a single GeoTIFF. It must match the submission format's CRS, shape, and geotransform.

Note (optional): a short comment to help you tell submissions apart later, e.g. clustering with k=25. Keep it <= 140 characters.

→ Open DrivenData submission page

📗 Step-by-step

  1. Log in to DrivenData and accept the GEMS Prize Challenge rules.
  2. Download the validated TIF from the home page: gemsdoe-karage2-hkarage1-irregular-submodular-15000d-6a3f542a-zeros.tif (SHA-256: 28451a64…5fbfff).
  3. Verify locally before uploading (this is what the project does automatically):
    • single band, float32;
    • CRS = EPSG:32611, 3730×3292 pixels, 100 m resolution;
    • geotransform = (100, 0, 243350; 0, -100, 4508550);
    • every cell finite and in [0, 1] — this is what causes the portal error "Predicted values must be in range [0, 1]"; our TIF is byte-verified finite in range;
    • no NaN inside the footprint.
  4. Name it uniquely on the form, e.g. gemsdoe-karage2-hkarage1-irregular-submodular-15000d-6a3f542a-zeros.
  5. Add a short note (<=140 chars), e.g. GEMSDOE H-KARAGE-1 irregular submodular 15k dots | lattice-avoid placement | 6a3f542a | research DO-NOT-SUBMIT-yet.
  6. Submit. One submission is scored in both the Initial Prize Round (private expert-labeled test set) and the Final Prize Round (expanded label set after expert review) — choose it before the deadline.

🔎 If the portal returns "Predicted values must be in range [0, 1]"

That error means the GeoTIFF contains values outside [0, 1] or non-finite cells (NaN/Inf). The generated TIF here is verified byte-wise: finite everywhere, min 0.0, max 1.0. If you regenerate, run the same 13-check validator (scripts/submission_writer.py) before uploading.
