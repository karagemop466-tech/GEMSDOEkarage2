File to submit: a single-band GeoTIFF (.tif), or a .zip containing a single GeoTIFF. It must match the submission format's CRS, shape, and geotransform.

📗 Step-by-step (2026-10-28 candidate)

  1. Log in to DrivenData and accept the GEMS Prize Challenge rules. Check your remaining weekly quota on the submission page (this project cannot see it).
  2. Download the validated TIF from the home page: gemsdoekarage2-k2-hgbcont-b110-20261028-zeros.tif and verify SHA-256 = 504be4587e3bec7b81f802b4c16b6c546c683e8a4c8b514d3a9856c6e0698dfb. Do not use any older file from this site (the earlier H-KARAGE-1 file named on previous versions of this page was found defective on 2026-10-28 and must not be submitted).
  3. Verify locally before uploading (already done automatically by the project; receipts beside the download):
    • single band, float32;
    • CRS = EPSG:32611, 3730×3292 pixels, 100 m resolution;
    • geotransform = (100, 0, 243350; 0, -100, 4508550);
    • every cell finite and in [0, 1] — values outside [0,1] or NaN/Inf cause the portal error "Predicted values must be in range [0, 1]"; this TIF's cells are exactly 0.0/1.0, read-back verified;
    • no NaN anywhere; outside-footprint cells are 0.
  4. Attach the file (the .tif, or the .zip containing the identical single .tif).
  5. Add the Note (108 chars): K2 supervised HGB 26f + tip continuation, dotted emission 1.10%, off-catalogue >2px; zeros outside footprint
  6. Submit. Save the organizer's receipt and score — it becomes the project's first ORGANIZER-CONFIRMED number. Remember one chosen submission is scored in both prize rounds; confirm final-selection rules on the official page before the deadline.

🔎 If the portal returns "Predicted values must be in range [0, 1]"

That error means the uploaded GeoTIFF contains values outside [0, 1] or non-finite cells under the portal's reading. The K2 TIF is verified cell-by-cell: finite everywhere, min 0.0, max 1.0, nodata = none. If you regenerate any file, re-run the shared writer/validator (vendor/gems57/submission_writer.py via scripts/k2.py) and confirm the downloaded file's SHA-256 matches the receipt before uploading. If the portal still rejects the zeros-outside encoding, tell the project — a NaN-outside variant can be written by the same writer, but it reintroduces NaN cells, so do not improvise it without a portal receipt showing which encoding was rejected.
