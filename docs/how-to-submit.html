How to make a submission into the contest (when a file is cleared)

Do not upload any current file. These instructions are conditional; neither inspection nor a format pass bypasses the literal duplicate stop. No file in this repo is currently cleared for a weekly submission slot.

Official format (problem page 967): a single-band GeoTIFF (.tif), 32-bit float, values between 0 and 1, CRS EPSG:32611, 100 m resolution, same bounds/shape/geotransform as the training template. Data outside the bounds is null or NaN.

Official rules (NLR PDF §1.1, §3.2): one entry per competitor; a single GeoTIFF with a single raster layer; up to three submissions per week; one final selection per entity; generative-AI use must be described in the narrative.

  1. Generate—not copy—a candidate. Run an assigned lane using the shared feature stack, evaluator (evaluate_holdout.py) and writer (submission_writer.py). Use buffered whole-segment hide-and-recover; derive catalogue features from visible faults only; mask visible faults pixel-exactly. Never rename, jitter or re-encode a submitted mask to claim novelty.
  2. Test every input feature alone for leakage. AUC above 0.90 on a feature alone is suspect until proven otherwise. H-B's canary: alteration 0.488, magnetic edge 0.523, gravity edge 0.536, curvature 0.481, combined 0.498 — all pass (no leakage).
  3. Recheck the exact final TIFF. Verify a single float32 band, matching CRS/shape/transform, no non-finite or out-of-range values inside the footprint. Reconcile the official null/NaN exterior guidance with the portal range behavior; neither convention is assumed accepted.
  4. Pass every automated gate before a slot is considered. Format, holdout-DTI (pooled, alpha 0.2 / beta 0.8 / 300 m triangular kernel, spatial-block CI), and uniqueness (|Spearman| ≤ 0.90 AND ≤ 70% of dots within 3 px of any registry raster).
  5. A separate selector checks the account quota. Promotion to a weekly slot is separate from a model run. Retrieve current rules and remaining quota from the authenticated submission page; never invent a quota. No file is currently promoted.
  6. Only after clearance: download and upload. Download the approved .tif, verify its SHA-256 against the approved receipt, sign in to the DrivenData submissions page, choose the file, and use the recorded unique name and a short note no longer than 140 characters. ZIP upload acceptance was not verified. Save the actual organizer receipt; never promote a projection into a score.
About the "Predicted values must be in range [0, 1]" portal error: this fires when the portal reads any value outside [0, 1] — including NaN, infinity, or a finite nodata sentinel. H-B avoids it by keeping every pixel finite and inside [0, 1] (zeros outside the footprint). The official wording also permits null/NaN outside the bounds; that exterior convention is unresolved in this checkout, so a local format pass does not guarantee portal acceptance. Validate the actual on-disk file before uploading.

Our checks require no human inspector. The current blocker is missing/contradictory evidence and an unassigned lane, not a request to waive a gate. No account credentials are stored by this project.
