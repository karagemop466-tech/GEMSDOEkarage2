2. Why the GEMSDOE32 file scored 0.2778 (and why none of the nine should be re-submitted)

Metric. The competition scores a single-band raster with a distance-tolerant Tversky index: α = 0.2 on false positives, β = 0.8 on false negatives, 300 m triangular kernel, mapped-fault pixels excluded (official problem page, confirmed in the organizer reference notebook which trains with the same α/β). Writing it as DTI = T / (0.2·T + 0.2·F + 0.8·G) with T the kernel credit on hidden-truth pixels, F the false-positive mass and G the hidden-truth total makes the arithmetic below exact.

Calibration (E1, evidence/calibration/leaderboard_calibration.json). The r13 lattice file (206,895 dots on a regular grid; user-reported 0.0904) covers every footprint pixel within 3 px, so its kernel credit per truth pixel is a geometric constant (c = 0.3746); solving the identity gives G ≈ 12,406 px (interval 12,397–12,414 from score rounding), about 20.3% of the public catalogue's pixel count. The lattice's credit per truth pixel measured on our catalogue holdout (0.3736) matches that constant, which is the one check of the calibration that the public data allows.

Nested family. Exact set relations on the pinned bytes: GEMSDOE25 ≡ GEMSDOE30 (44,090 dots); GEMSDOE31 = GEMSDOE25 minus 3,891 dots all ≤ 1 px from a mapped fault; GEMSDOE32 = GEMSDOE31 minus 2,545 dots in the 1–2 px band; GEMSDOE36 = GEMSDOE32 + 1,200 dots. If a removed set carries zero truth credit, 1/DTI changes by exactly −0.2·Δn/T, so the 0.2600 → 0.2708 step implies T ≈ 5,073, and the B2 point is T ≈ 5,073, M ≈ 1,038 hit-dots (2.8 % of 37,654), F ≈ 36,616. GEMSDOE32 is the best of the nine because it deleted the dots that could not score, not because it found more faults. Deleting its remaining 2–3 px band would project ≈ 0.2846 — but that file would be a strict subset of GEMSDOE32 and therefore not unique.

Marginal-dot rule. A dot pays off only if its expected truth share exceeds α·DTI ≈ 0.056; with the hidden corridor (≤ 3 px of hidden truth) covering ≈ 1.75 % of the footprint, that is ≈ 3.2× base-rate enrichment. This is why budgets near 40–50 k dots are optimal for a surface of this quality and why 60 k-dot files (GEMSDOE24/27) scored lower.

3. What HK3 did (the submitted file)

  • Lane (single method): HK3 (self-declared; no coordinator paragraph supplied): catalogue-free edge-centrality surface + calibrated off-catalogue dot emission.
  • Hypothesis: Thin linear slope maxima of detrended elevation (gradient-ridge centrality, structure-tensor coherence) and amplitude-normalised potential-field edges (gravity/magnetic tilt-angle zero-crossing distance) mark fault scarps that 1:100k mapping missed; a per-fold HGB on 34 bands learns them from visible faults only.
  • Mechanism: Scarps are linear maxima of slope; range-front and intrabasin faults juxtapose density/magnetisation contrasts whose tilt-angle zero crossing sits over the edge independent of amplitude; 3 px catalogue apron and 3 px separation follow the calibrated metric geometry (E1).
  • Named non-fault mimic: lithologic/intrusive contacts (same potential-field step), pluvial shorelines and terrace risers (linear slope maxima), survey flight-line striping.
  • Protocol: shared evaluator gems57-pooled-hide-v2; K2 label-blind quadrant folds, 80 px buffer, visible faults masked pixel-exactly, model refit per fold; catalogue features from visible faults only; α 0.2 / β 0.8 / 300 m triangular kernel; paired spatial-block bootstrap (158 blocks, 2000 draws).
  • Leakage canary: max single-feature AUC 0.596 (limit 0.90) — pass for all eight new bands.
  • Holdout arms (HOLDOUT-DTI, same folds): candidate 34-band at 0.73 / 1.10 / 1.50 % budgets 0.1545 / 0.1845 / 0.2092; re-fitted K2 incumbent 26-band 0.1261 / 0.1575 / 0.1826 (the 1.10 % incumbent reproduces the recorded K2 number 0.1581 exactly). Paired Δ at 1.10 %: +0.0270 [0.0206, 0.0337].
  • Transfer anchors (bridge): at the D2.8 family's own dot count on the same folds, HK3's dots cover 11.4% more withheld-fault credit with a 15.6% higher per-dot hit rate.
  • Budget rule (pre-registered, section 3b of the hypotheses note): maximin of the calibrated estimate over θ ∈ {1, 0.75, 0.5} → rate 0.9 % of active pixels → 45,108 dots. argmax at θ = 1 would be 1.5 % (flat curve, more downside).
  • Estimate at the chosen budget: T ≈ 5,650, M ≈ 1,438, F ≈ 43,670, G ≈ 12,406 → 0.2855 (LEADERBOARD-CALIBRATED ESTIMATE).

Why no cross-family out-of-sample check is possible

Three further owner-reported files (gems10 ridge surface 0.128, gems10 dotted ridge 0.1839, ens12 0.1563; scores from GEMSDOE24's calibration manifest) were run through the same estimator and were over-predicted 1.5–2.9×. Every external file was built with the full catalogue visible, and a model that has seen the withheld segments gets 2.89× the catalogue-holdout coverage of the clean per-fold model at the same dot count (leakage_inflation.json). Those checks therefore cannot test the transfer rule; they are recorded in anchors_out_of_sample.json and not used. The HK3 holdout numbers are leakage-free by construction (per-fold refit; all canaries pass). If the D2.8 anchor is itself mildly leaked, the estimate above is conservative.
