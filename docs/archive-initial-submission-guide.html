Automated release gates

  1. Pin the assigned method, shared feature cache, evaluator, writer, and registry snapshot.
  2. Withhold whole fault segments with a buffer. Recompute catalogue features from visible faults only; mask those faults pixel-exactly.
  3. Run individual-feature leakage canaries. AUC above the specified threshold blocks promotion.
  4. Compute pooled HOLDOUT-DTI using the shared evaluator with the requested triangular kernel. Record evaluator version, withheld positives and confidence interval; compare the current best under identical folds.
  5. Check rank correlation and dot proximity on both the surface and final dots. Stop on duplicate-lane detection.
  6. Use the shared writer. Reopen the TIFF and verify one band, finite footprint values, range [0,1], and exact CRS, shape and transform against the organizer template. Record SHA256.
  7. Release only after all gates pass. A separate selector checks the actual weekly cap before upload.

When an approved file exists

Download the approved single-band .tif; keep its checksum and run card. On DrivenData, choose New submission, select that TIFF and paste its short note. Save the resulting receipt. Only that receipt can establish an ORGANIZER-CONFIRMED result. This static site does not submit files or know your remaining weekly allowance.

The range error may come from nodata sentinels, infinities, or out-of-range predictions; its exact cause cannot be determined without inspecting the rejected file. Do not fix it merely by clipping a scientifically invalid raster.
