What a safe release requires

These requirements are sequential. Stop if any gate fails; do not replace a failed candidate with an old research raster.

  1. Establish the lane and registry. Confirm the assigned method paragraph, resolve the calibration-lattice policy explicitly, and obtain the complete current registry and the frozen, same-evaluator best. Under the current literal rule, the H33-sized budget is already a duplicate stop.
  2. Validate the science. Run the shared segment-held-out, buffer-aware pooled evaluator; derive catalogue features only from visible labels. Test every feature alone for leakage, and report HOLDOUT-DTI, evaluator version, withheld positives and a 95% confidence interval. Do not extrapolate it to a public score.
  3. Screen for duplication. Compare surface rank correlation before placement and final-dot overlap after placement against every registry raster. Stop when rank correlation exceeds 0.90 or more than 70% of dots are within 3 pixels of any one reference.
  4. Write and validate the exact file. Use the shared writer and validator. Verify single-band float32, EPSG:32611, expected shape and transform, finite values in [0,1] inside the footprint, and the official outside-footprint convention. Save and verify the SHA-256 of the exact final file.
  5. Wait for the separate selector. A scientifically qualified candidate is not automatically an authorized competition entry. The selector must compare it to the best matched holdout, check available slots and decide whether to promote it.

When a candidate is actually authorized

  1. Confirm that the exact selected TIFF’s SHA-256 matches the run card. The selector will assign an unused filename and a note of at most 140 characters. There is no filename or note to copy now.
  2. Sign in to the official submissions page, check the quota shown there, and follow its upload controls for the selected TIFF. We could not inspect the authenticated page, so field labels are not assumed.
  3. Record the resulting organizer receipt, file hash, timestamp, name and score together. A public team leaderboard row alone does not prove which file received a result.
